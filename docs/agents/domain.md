# 领域文档约定

本仓库采用 single-context（单一上下文）领域文档布局。本文件说明工程类 Skill 在探索代码前应如何读取领域资料。

## 探索前读取

- 如果仓库根目录存在 `CONTEXT.md`，先读取其中的领域术语和概念边界
- 如果根目录存在 `CONTEXT-MAP.md`，按其中的指引读取与当前任务相关的 `CONTEXT.md`
- 按 `docs/README.md` 的任务路由读取对应主文档
- 阅读 `docs/adr/` 中与当前工作区域相关的 ADR

某个文件不存在时继续执行，无需报告缺失，也无需预先创建。`domain-modeling` 会在领域术语或架构决策真正明确后按需创建相应文件。

## 文件布局

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-example-decision.md
│       └── 0002-another-decision.md
└── src/
```

## 使用领域词汇

Issue 标题、重构建议、假设和测试名称涉及领域概念时，应使用 `CONTEXT.md` 定义的术语，并保持全文一致。

需要使用的概念尚未出现在词汇表时，应先确认它是否为现有概念的同义表达。确实缺少相应概念时，再通过 `domain-modeling` 补充领域词汇。

## 标明 ADR 冲突

输出内容与现有 ADR 冲突时，应明确指出对应 ADR 及重新讨论该决策的理由，不得直接覆盖既有决策。
