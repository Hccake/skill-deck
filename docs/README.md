# Skill Deck 文档

Skill Deck 的长期文档描述当前产品、领域和系统约束。每项稳定事实只由一份文档负责；其他文档只保留读者理解当前主题所需的摘要，并链接到负责文档。源码、公共类型和测试承担可执行细节，长期文档不复制组件实现，也不维护能够直接从代码获得的完整清单。

## 文档地图

| 文档 | 唯一负责内容 | 发生什么变化时更新 |
|---|---|---|
| [产品设计](./product.md) | 用户心智模型、页面能力、用户工作流、反馈规则、Agent 筛选交互和产品限制 | 用户可见能力、交互语义或产品限制变化 |
| [Agent](./agents.md) | Agent 注册表、定义、读取能力、检测、关联 Agent、筛选候选、选择分组和默认目标 | Agent 模型、解析规则或选择语义变化 |
| [Environment 与 Context](./environments-and-contexts.md) | Environment、Context、项目绑定、路径解析条件和存储访问 | 执行位置、工作范围、项目绑定或存储归属语义变化 |
| [Skill 生命周期](./skill-lifecycle.md) | 来源、发现、安装、读取、更新、来源修复、管理 Agent、复制和移除 | Skill 从来源到本地状态的业务语义变化 |
| [系统架构](./architecture.md) | 系统边界、技术分层、运行时职责、进程通信、窗口、平台实现、快照一致性和系统级安全边界 | 顶层分层、依赖方向、窗口、传输边界或运行时职责变化 |
| [测试与验证规范](./testing.md) | 测试分层、测试夹具、跨平台边界、断言规则和验证证据 | 测试架构、平台测试能力、测试夹具或验证策略变化 |
| [执行与恢复](./execution-and-recovery.md) | 内容快照、预览与执行、变更、路径安全、原子写入、取消和恢复 | 写入协议、一致性、安全或恢复边界变化 |
| [skills CLI 兼容](./skills-cli-compatibility.md) | 上游 CLI 基线、共享格式、锁文件、哈希、稳定差异和同步检查 | CLI 版本或互操作边界变化 |
| [贡献指南](../CONTRIBUTING.md) | 开发命令、前端与后端协作、验证、CI 和发布流程 | 开发、验证或发布流程变化 |

仓库根目录的 `README.md` 与 `README.zh-CN.md` 面向最终用户，`CHANGELOG.md` 记录版本变化。`AGENTS.md` 和 `CLAUDE.md` 只提供 Agent 执行规则，不承担产品或架构说明。

| 新增或修改测试、测试夹具、平台适配器验证或 E2E | [测试与验证规范](./testing.md)；修改 CI 命令时增加[贡献指南](../CONTRIBUTING.md) |

文档与实现发生冲突时，需要判断实现是否偏离已确认设计，或者文档是否已经过期，并在同一变更中恢复一致性。不能用另一份非负责文档掩盖冲突。

## 架构决策记录

[`docs/adr/`](./adr/) 只记录具有长期价值的架构取舍、放弃的方案和重新讨论条件，不重复当前行为的完整规则。当前行为仍以文档地图中的负责文档和代码、测试为准。

## 写作规则

- 正文使用符合中文语境的陈述体；必要的专业术语可以保留英文原文。
- 长期文档只描述当前状态，不记录迁移过程、旧方案或阶段性的界面取舍。
- 稳定术语由对应负责文档在首次出现时自然定义，其他文档复用同一表达；不维护集中术语表。
- 非负责文档最多保留当前主题需要的一段摘要，不复制状态表、规则清单或算法步骤。
- 产品文档不记录组件结构、布局尺寸、图标、提示框或内部状态组织。
- 架构和执行文档可以记录跨模块契约、安全边界和长期不变量，不维护源码调用链或内部辅助函数清单。
- 图示用于表达结构、状态或时序关系，简单事实使用正文或表格。
- 不手工维护完整的 Agent、命令、类型、组件、状态管理模块、模块或制品文件名清单。
- 每次变更只更新真正拥有该事实的长期文档。
