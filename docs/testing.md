# 测试与验证规范

Skill Deck 需要在 Windows、macOS 和 Linux 上处理文件、启动进程并运行桌面界面，Windows 还涉及 WSL。测试既要尽快发现规则错误，也要覆盖不同操作系统、真实文件系统和桌面运行时中的关键行为。开发者应根据改动内容选择相应测试，并在交付时说明实际运行的平台和尚未验证的场景。

## 测试类型与覆盖范围

测试类型按照实际运行方式划分，各类测试相互补充。使用模拟依赖的测试适合检查规则、接口和异常处理；涉及操作系统或桌面运行时的行为，还需要在对应环境中检查。

| 测试类型 | 适用内容 | 主要检查内容 | 需要另行检查的内容 |
|---|---|---|---|
| 纯规则测试 | 解析、哈希、计划、状态转换和错误映射 | 给定输入能否得到确定结果，领域规则是否成立 | 文件读写、进程、网络和桌面运行时 |
| 接口与契约测试 | 命令输入输出、序列化、窗口命令权限和协议 | 类型是否一致，命令是否注册，权限和错误分类是否正确 | 真实 WebView、目标操作系统和外部服务 |
| 工作流集成测试 | 临时目录、本地 Git 仓库、本地 HTTP 服务和多个模块之间的协作 | 文件读写、冲突处理、失败清理和工作流状态变化 | 其他操作系统、真实 WSL 发行版和桌面窗口协作 |
| 目标平台测试 | Windows、macOS、Linux 的平台分支、加载器、链接和随应用发布的脚本 | 对应操作系统上的编译、进程启动和平台特有行为 | 尚未运行的平台、真实 WebView 和 Windows 与 WSL 之间的完整流程 |
| 桌面应用验收 | 真实 Tauri 应用、插件、WebView、窗口和关键用户流程 | 应用能否启动，桌面运行时中的跨层协作是否正常 | 未执行的外部环境和纯规则的其他输入组合 |

测试名称应与实际运行方式一致。Tauri 模拟运行时（`MockRuntime`）、前端模拟实现（mock）和本地测试服务器不会启动原生 WebView，使用这些能力的测试不属于桌面应用验收。具体限制见 [Tauri 测试说明](https://v2.tauri.app/develop/tests/)。

Rust 单元测试使用 `MockRuntime` 构建 Tauri 应用时，测试夹具只提供被测行为需要的配置和资源。优先使用 Tauri 的测试上下文；确需通过 `generate_context!` 读取应用配置时，使用测试模式，避免测试二进制生成只属于真实应用运行时的资源。

## 选择和编写测试

1. 先确定需要防止的错误、预期结果和需要区分的失败类型，再选择测试类型。
2. 缺陷修复先增加能够复现同一问题的最小测试。完成修复后，确认测试可以识别绕过规则或遗漏异常处理的实现。
3. 解析、状态转换等纯规则优先放在运行快、失败原因清晰的测试中。文件、进程、网络和桌面运行时行为使用相应的真实依赖补充检查。
4. 平台无关的规则在 Windows、macOS 和 Linux 上运行；使用平台 API 或平台特有文件语义的代码在对应操作系统上测试。
5. 测试主动控制时间、并发、网络和环境变量。外部进程、监听端口和临时目录都要设置超时，并在测试结束后完成清理。

### 长期测试的保留标准

长期测试保护稳定的产品行为、公共契约、兼容格式、安全限制或已知缺陷。测试应在这些行为被错误修改时失败，并允许实现结构、组件拆分和视觉细节在行为不变时正常调整。

- 前端行为测试通过可访问名称、可见状态和用户操作观察结果。除设计系统本身的测试外，不断言 Tailwind 类名、具体 Lucide 图标类名、内部 `data-slot`、固定网格列定义或其他组件实现细节；需要检查视觉层级、间距和响应式布局时，使用目标视口下的桌面验收或视觉回归。
- 已完成迁移后，不长期保留“旧字段、旧文案键或旧函数名不得存在”的反向断言。仍需持续禁止的安全字段、敏感信息和领域禁用语应由明确的长期规则、类型约束或专用静态检查维护。
- 薄传输包装器只测试自身增加的行为，例如错误解包、默认参数、参数形态转换和事件 Channel 适配。不为每个类型安全的原样转发函数重复验证调用参数。
- 同一展示模块的名称、数量、顺序和状态由该模块的接口测试覆盖。父级页面只验证是否正确使用该模块及自身工作流，不重复检查子级图标和布局结构。
- `tauri-specta` 在 debug 应用启动时根据正式命令注册生成 bindings；生成文件进入版本控制。CI 使用普通契约测试在临时目录生成同一内容并与正式文件比较，测试只承担自动判定职责。
- 临时实施约束只在开发过程的 spec 或 ticket 中跟踪。迭代完成时删除仅用于限制迁移步骤、源码组织或中间命名的测试，保留最终行为对应的覆盖。

## 跨平台测试

### 本机路径与 POSIX 路径

本机路径由桌面应用所在的操作系统解释。Rust 代码和测试使用 `Path`、`PathBuf`、`join` 和 `components` 等平台接口构造并比较这类路径。

判断两个本机路径是否相同、是否存在父子关系时，应比较路径组件。业务代码和测试不应通过查找 `/` 或 `\`、替换分隔符或拼接带分隔符的字符串来判断路径关系。需要处理另一操作系统的路径时，应使用明确的解析器或值类型，并在接口处完成本机路径与协议值之间的转换。

WSL、远端 Unix、Git 协议和脚本参数中的 POSIX 路径是协议数据，不使用当前操作系统的 `Path` 规则解释。相关测试需要覆盖根目录、`.`、`..`、绝对路径、相对路径和符号链接目标。

### 条件编译与平台覆盖

`#[cfg(unix)]` 和 `#[cfg(windows)]` 只用于依赖对应操作系统 API、权限或进程能力的代码和测试。解析、协议和业务规则应在所有平台上编译和运行。

平台专属的导入、常量、辅助函数、测试夹具和实现应使用相同的 `cfg` 条件保护，避免其他目标在 `-D warnings` 下出现未使用代码。`#[cfg(test)]` 只表示测试构建会包含这段代码，不能说明它已经在 Windows、macOS 和 Linux 上执行。

新增或修改平台分支后，应在对应操作系统上完成编译、Clippy 和测试。常规 CI 无法覆盖的真实环境检查可以安排在手动验证、定时任务或发布流程中，并在交付说明中记录结果。

### Cargo 测试目标与 Windows 可执行文件

`cargo test` 默认编译并运行库、二进制和集成测试中的测试函数，同时运行文档测试。示例默认参与编译，但不会执行，除非对应目标显式启用测试。每个集成测试文件都会生成独立的测试可执行文件。具体规则见 [Cargo test](https://doc.rust-lang.org/cargo/commands/cargo-test.html) 和 [Cargo targets](https://doc.rust-lang.org/cargo/reference/cargo-targets.html)。

涉及 Windows manifest、Common Controls、动态库、资源文件或原生插件时，完成编译后还要在 Windows 上启动相应的测试可执行文件。窗口、插件和 WebView 之间的协作需要在真实桌面应用中检查。

### Unix Shell 与 WSL

直接执行 `/bin/sh`、依赖 Unix 权限位或 POSIX 系统调用的测试使用 `#[cfg(unix)]`。随应用发布且依赖 GNU 用户态工具的 WSL 脚本，在 Linux 上运行真实脚本测试。

WSL 测试按运行环境分工：

| 验证层级 | 主要覆盖 |
|---|---|
| 跨平台协议测试 | 请求响应、版本、乱序、分块传输边界、累计截止时间、请求已发送但结果未知、超时后的迟到响应 |
| Linux 文件系统引擎测试 | 路径大小写、链接、权限、执行位、非 UTF-8 路径、有界读取、目录身份、内容清单和条件写入 |
| Linux 真实 Worker 测试 | 握手、身份与摘要、路径转换、调度公平性、来源和内容句柄、双向传输、文档及目录事务、取消和结果确认 |
| ShellCheck 与 Linux 脚本测试 | 最小身份探测的语法、字段、输入输出和退出状态；通过受控 `PATH` 确认 Git 等业务工具不参与连接 |
| Windows 与真实 WSL 2 联合验证 | 发行版筛选、Worker 准备与部署、`wsl.exe` 传输，以及下表中的实际读写流程 |
| Worker 制品验证 | musl 目标、摘要清单、构建标识、SHA-256、安装包资源和部署升级行为 |

真实 WSL 验证保留以下入口：

| 流程 | 测试入口 |
|---|---|
| Skill 读取 | `real_wsl_worker_executes_a_skill_read_plan` |
| 大规模读取与路径事实 | `real_wsl_worker_inspects_more_than_one_root_batch`、`real_wsl_worker_projects_and_inspects_more_than_one_transport_batch` |
| CLI 专用目录安装的读取与原位置更新 | `real_wsl2_private_only_update_preserves_layout` |
| 项目父目录链接指向外部内容、仅剩外部内容时的零写入 | `real_wsl2_project_update_preserves_external_content` |
| CLI Eve 目录读取、已记录缺失位置恢复与单文件阻断 | `real_wsl2_eve_update_restores_recorded_missing_installation` |
| 专用目录复制、项目身份比较、管理 Agent 与移除 | `real_wsl2_private_only_copy_manage_and_remove` |
| 单文档条件写入与兼容 lock 字段保留 | `wsl_history_round_trip_preserves_unowned_global_fields` |
| Git 分支与标签区分、深层来源元数据读取、内容准备与释放 | `real_wsl2_worker_completes_git_scan_payload_and_release` |
| Windows 获取 HTTP 内容、释放原始来源后在 WSL 执行已准备内容 | `real_windows_http_payload_executes_in_wsl_after_source_release` |
| 目录事务、恢复标记与成功确认清理 | `real_wsl2_worker_executes_and_acknowledges_one_remove_transaction` |

联合验证默认使用 Ubuntu，也可以通过 `SKILL_DECK_TEST_WSL_DISTRO` 指定发行版。无论成功或失败，都要清理 WSL 测试目录。

Worker 制品在 Windows 调试构建中检查 Tauri 资源目录。NSIS 在一次性 CI runner 中静默安装、校验资源并卸载；MSI 通过管理提取校验资源。部署覆盖首次写入、相同摘要复用、损坏替换、升级后回退、非普通目标拒绝和临时文件清理。

Linux 和跨平台协议测试不能代替 Windows 与真实 WSL 的联合验证。首个业务纵向切片通过联合验证后，再批量迁移依赖同一底层能力的调用方。

Shell 测试捕获标准输出、标准错误和退出状态，设置超时并清理子进程。用户输入通过位置参数或结构化标准输入传递。ShellCheck 警告作为失败处理，必要的忽略在代码附近说明原因。

## 测试夹具与外部依赖

### 文件系统与 Git

文件系统工作流使用真实临时目录，并由创建夹具的测试负责清理。测试根据目标平台覆盖目录不存在、目标已存在、悬空链接以及删除链接后保留目标内容等情况。Windows 目录联接（junction）、重解析点（reparse point）和 Unix 符号链接的测试应关注产品行为。只有测试平台适配层本身时，才直接断言操作系统返回的原始字符串或枚举值。

测试使用当前平台的路径接口构造本机路径，JSON、WSL 和其他协议中的 POSIX 路径使用独立表示。依赖当前目录、用户主目录、系统语言、Git 配置或环境变量的测试应显式设置这些条件，并在结束后恢复进程状态。

需要保持字节稳定的 Git 夹具通过 `.gitattributes` 和显式写入控制换行符。哈希测试应说明是否包含可执行权限等元数据；目标平台无法表达某项元数据时，为不同平台分别准备测试样例。平台验收使用对应操作系统原生创建的检出或测试仓库。

### 第三方 CLI 安装兼容

兼容测试使用锁定的 `skills` 开发依赖，通过 Node 执行真实 CLI，在隔离的项目与用户目录中生成文件和 lock。先断言实际安装形态，再由 Skill Deck 的应用流程验证读取、检查、准备、确认和文件结果。CLI 自身执行成功不代表 Skill Deck 已通过兼容验证。

| Native 入口 | 主要覆盖 |
|---|---|
| `native_update_private_only_cli_installation_in_place` | 单 Agent 默认复制、双 Agent 显式复制；通用目录缺失时原位置更新并保持布局 |
| `native_eve_update_restores_recorded_missing_installation` | Eve 记录识别、缺失恢复、差异确认、过期拒绝与单文件阻断 |
| `native_private_only_copy_manage_and_remove_preserve_source_layout` | 固定实际复制源、来源歧义、格式校验、关联和移除 |
| `native_copy_project_identity_resolves_directory_links_and_rejects_missing_roots` | 本机目录链接、同项目、父子目录及缺失项目拒绝 |
| `native_project_update_*` | 项目实际根、库隔离、外部内容保留、零写入及确认后链接改指 |
| `native_update_preview_groups_sources_and_exposes_read_only_link_locations` | 来源共享准备、通用位置标识与只读链接投影 |

前两个入口依赖 Node 和 CLI，使用显式 ignored。现有三平台 Rust tests 矩阵先准备锁定依赖，再单独运行过滤器并核对成功测试名；普通 Cargo 规则测试继续支持不安装 Node 的场景。

Windows 与真实 WSL 的对应入口见前表。目标发行版需要可用的 Node 和固定版本 CLI，通过 `SKILL_DECK_TEST_WSL_NODE` 与 `SKILL_DECK_TEST_WSL_CLI` 指定。夹具替换来源获取以控制输入，目录观察、内容存储、读取、事务和 lock 提交使用真实 Worker；不向产品协议增加任意命令接口。

多目录和库归属回归还需覆盖：活动及退役库成员、根目录链接、同一物理位置的多个读取者、全部差异保留时不写 lock、准备后目标变化，以及必要位置失败时整项阻断。项目复制另需验证 Windows 挂载、Native/WSL 别名及所属发行版身份。

多路径 Worker Adapter 的边界测试至少覆盖上限值、上限加一和多批次输入，确认调用方不感知协议批次，结果顺序与全局索引保持一致，所有批次共用取消信号和累计截止时间。metadata 页同时受 256 项和 8 MiB 最坏内容预算约束，并发页数不超过 8。

Skills 读取的固定规模夹具包含 100 个 Agent 根、1,000 个逻辑 Skill 和 10,000 个实际位置，断言只处理实际条目和根链接事实，每个唯一物理内容最多读取和解析一次，指纹未变的刷新命中进程缓存，指纹变化后重新读取。Windows Host 与真实 Ubuntu WSL 2 使用 Release 构建连续执行至少 20 次冷加载，P95 不超过 5 秒；Linux 规则测试、Debug 构建或缓存命中结果不能替代该门禁。

### HTTP、时间与外部进程

配置读取与修复测试覆盖故障隔离、上一次有效值的保留、未修改字段的保留、修复保存、外部修改冲突和写入结果未确认的处理，并区分内存快照与磁盘变更。共享 HTTP 传输测试确认配置不可用时停止请求。

HTTP 测试使用成熟的本地服务器库，Git 测试使用可控仓库或可替换的传输实现。测试夹具应能稳定产生认证失败、远端引用变化、响应不完整、限流、网络中断、克隆失败和超时等结果。具体重试时间、缓存范围和限流规则由[更新检查](./update-checking.md)及其测试维护。

网络测试按接口职责分工：

| 对象 | 主要覆盖 |
|---|---|
| 共享 HTTP 传输 | 直接连接、单个自定义代理、新请求读取最新设置、客户端重定向、总时限、取消和读取上限 |
| 内容消费模块 | 响应格式、媒体类型、内容大小和解包限制 |
| Discover | `www.skills.sh` 站点和公开 `/api/search` 路径契约 |
| Git 适配器 | 命中范围时注入进程级代理参数，其余情况保留原连接方式，不修改持久化 Git 配置 |
| WSL Git | 跟随 Windows Git、使用发行版可访问的独立代理，或者保留发行版配置 |
| 诊断 | 输出有界，应用持有的认证 Header、密码和 Token 不被主动写入日志；不要求改写第三方 Git 原始输出 |

这些测试覆盖应用主动发起的请求。WebView 图片需要另行验收，连接测试也不能证明其他地址可访问。官方客户端内部行为不重复测试，网络信任边界由[系统架构](./architecture.md#外部网络访问)维护。

时间、随机数、端口和并发完成时机由测试控制。等待结果使用通道、带截止时间的等待或测试库同步能力，避免通过固定等待掩盖竞争。

文件事务测试使用真实临时目录，并通过通道或显式通知控制并发修改。Native 适配器验证本机原子操作；WSL 协议与 Worker 测试验证请求和事务，再由 Windows 联合验证覆盖完整链路。

Git 进程夹具分别向标准输出和标准错误写入超过管道容量的数据，确认两条管道持续排空且诊断有界。进程超时和取消测试确认终止与回收；WSL 常驻 Worker 则按事务阶段验证取消、终态等待和会话关闭。需要真实 Git 行为时使用本地仓库或 `file://` 传输，只检查应用决策时使用可控传输。

## 后端测试

业务模块的接口是应用行为的主要测试入口。只有生产实现确实存在变化时才增加抽象；单一具体流程通过运行时模块和本地夹具测试。

| 层级 | 主要覆盖 |
|---|---|
| 纯规则 | 设置校验、解析、内容规则、版本选择和状态转换 |
| 工作流 | 预览、用户确认、执行、过期结果、部分完成、清理和错误映射 |
| 平台与存储适配 | 协议、序列化、原子文件操作、错误分类和目标平台语义 |
| Rust 命令与 IPC | 命令注册、输入输出、窗口权限和生成的类型绑定 |

Tauri Updater 适配器只验证应用增加的代理映射和官方签名或安装委托。取消窗口由 `ApplicationUpdater` 接口上的工作流测试覆盖，插件内部的端点回退、重定向和安装状态不重复测试。

被忽略的测试说明运行条件、执行方式和覆盖风险。共享夹具相互隔离，各测试显式控制当前目录、环境变量、时间和外部资源。

### Skill 库与目录规划

| 能力 | 应覆盖的行为 |
|---|---|
| 逐目录版本选举 | 组合直接安装版本、多个库版本、直接关联和库关联、共享物理目录、失效链接及冲突条目 |
| 完整维护流程 | 连续执行应用库、直接安装、调整 Agent、调整库顺序、移除直接安装 Skill 和取消应用；每一步检查全部相关目录 |
| 库候选读取 | 只依赖应用记录、库元数据和真实成员位置；一次规划只建立一份 Agent 目录表 |
| 无变化目录 | `Keep` 仍复核目录指纹和内容摘要，变化时返回过期；Native 与 WSL 都不产生目录、探针、备份或恢复标记 |
| 成员生命周期 | 新增、同名更新、退役、重新激活、跨 Scope 冲突、部分完成、重启后继续处理和清理阻断 |
| 库内容事务 | 同一 Environment 串行、不同 Environment 独立，内容与来源并发变化，添加更新回退和整库删除 |
| 已提交事务清理 | 后续目标状态不改变提交终态；清理失败后证据保留，连续读取仍可识别提交，权限恢复后完成清理 |
| 退役内容清理 | 退役只改变成员记录；引用检查完整后才能条件清理目录和记录，状态变化时保留内容 |
| 库应用执行 | 全部写目标预检查、Scope 整体停止、单个 Skill 的目录共同回退，以及其他已完成任务保留 |
| 未完成操作 | 配置调整、成员同步和主动重新应用的范围合并；普通检查失败不创建写入任务 |
| 连续成员变化 | 部分同步后退役、恢复原成员集合、移除后重新加入；保留无关成员被外部修改的目录 |
| 空闲检查 | 已同步且没有待办时，即使 Agent 或目录依赖不可用，也可以直接结束检查 |
| 引用与恢复 | 失效 Agent 的保留和明确解除、项目解除的条件删除；需要恢复状态来自持久化恢复记录 |
| 库应用格式 | 运行时位置由存储接口绑定，JSON 保存业务状态；未知字段、必填字段和结构版本按当前格式规则处理 |

WSL 写入探测测试确认文件操作结束后才返回超时终态，主进程无法取得终态时关闭会话。真实 WSL 联合验证覆盖正常探测、权限错误和后续写入。

业务预期以[Skill 生命周期](./skill-lifecycle.md#库应用与版本选举)为准，事务和格式预期以[执行与恢复](./execution-and-recovery.md#库内容事务)及[系统架构](./architecture.md#数据与状态归属)为准。

### 真实桌面自动化

`pnpm test:desktop` 使用 WebdriverIO 和 `@wdio/tauri-service` 的 embedded provider，在测试版 Tauri 进程中启动 WebDriver 服务。它操作应用自带的 WebView，无需额外安装 `tauri-driver`、EdgeDriver 或 WebKitWebDriver。运行前需要安装当前平台的 Tauri 构建依赖，并具备可见桌面会话；WSL 需要 WSLg。

```bash
pnpm test:desktop
# 仅修改 e2e 用例、复用已经构建的测试应用时
pnpm test:desktop --no-build
```

默认输出根目录为当前用户的 `.cache/skill-deck-validation/desktop`，可通过 `SKILL_DECK_DESKTOP_ROOT` 指定仓库外的固定目录。脚本打印本轮 `runs/<平台>-<随机标识>` 路径，其中保存截图、WebView 运行信息、日志和隔离数据。`target` 与 `dist` 用于增量构建；测试结束后关闭应用，运行证据保留供排查，确认不再需要时可删除对应运行目录。同一桌面会话按顺序运行测试。

测试通过独立 Cargo feature `desktop-e2e`、Tauri 配置和 Vite 配置启用自动化插件。正式构建默认不包含这些插件及其窗口权限。测试版使用独立应用标识、用户数据目录和 WebView 数据目录，并关闭 WSL 集成；该可执行文件仅用于本机验证，不作为发布制品。

当前用例覆盖主窗口启动、真实配置 IPC、设置页导航，以及 720×520、800×600、1000×760 内容区域下的浅色与深色主题。断言检查关键导航与横向溢出，截图用于人工或 Agent 视觉复核；截图成功本身不代表所有视觉细节均已验收。原生标题栏、系统对话框、托盘、多窗口及真实 WSL 操作需要补充对应测试或原生桌面验收。

设置侧栏用例检查 720px、800px、1280px 及 768px、1024px 阈值附近的实际布局：常用窗口显示全部分类名称，窄窗提供图标导航，缩窄后恢复原有排布。断言覆盖六个入口的名称显隐、侧栏宽度、按钮边界和内容横向溢出；组件测试覆盖导航名称与切换后的当前分类标记。

| 运行位置 | 实际验证的渲染环境 |
|---|---|
| WSL 内运行 Linux 应用 | WebKitGTK，通过 WSLg 显示 |
| Windows 原生工具链构建并运行 | WebView2 |
| macOS 原生工具链构建并运行 | WKWebView |

Windows 验收需在 Windows 原生工作区或受管理的验证副本内执行同一命令。首次构建前，运行 `pnpm prepare:wsl-worker -- --distro Ubuntu` 准备当前源码对应的 Worker 资源；用例本身保持 WSL 集成关闭。其他前置依赖见[开发环境说明](../CONTRIBUTING.md#开发环境)。WSL 中的结果只能证明 Linux 应用行为；浏览器预览用于前端快速检查，不能替代目标平台桌面验收。接入依据见 [Tauri WebDriver 文档](https://v2.tauri.app/develop/tests/webdriver/)。

端口默认使用 `127.0.0.1:4445`，可通过 `TAURI_WEBDRIVER_PORT` 调整；端口已被占用时，入口脚本直接报错。当前锁定的服务版本可能在会话结束时记录 `Failed to clear mock store: A sessionId is required for this command`，这是上游在会话销毁后清理 mock 的警告。判断退出是否正常时，应同时检查用例结果、应用进程和端口释放情况。

### 异步状态、定时器与焦点

组件通过状态、ref 回调或 React 提交阶段的 effect 驱动焦点和其他 DOM 副作用。需要在浏览器绘制前完成焦点调整时使用 `useLayoutEffect`。`setTimeout` 只用于产品明确要求的延迟，不用于协调同一次提交中的状态更新、元素挂载和焦点顺序。

测试先触发用户操作，再通过 `act`、`findBy*` 或针对可见结果的 `waitFor` 等待界面更新。产品包含防抖、延迟反馈或超时时，使用 Vitest 受控定时器，并在 `act` 内推进到明确的时间点。增加真实等待时间、反复轮询焦点或放宽超时不能解决竞争问题。

### 对象断言与模块 mock

对象结构本身属于接口约定时，测试应完整比较命令输入输出、持久化格式、协议消息或国际化结构。测试只关心调用方实际使用的部分字段时，使用类型化的部分对象断言，避免无关字段变化破坏调用方测试。

国际化结构测试比较语言包的键和数据形状，关键文案测试精确比较已经确认的文本，组件行为测试只检查当前交互需要的可见内容。

需要保留模块大部分真实行为、只替换少量依赖时，使用 `importOriginal` 创建部分 mock。只有在测试需要隔离整个接口时才使用完整 mock，并提供该接口的全部必需成员。mock 缺少新增成员，说明测试使用的接口没有同步更新；不应在生产代码中增加测试专用分支来绕过问题。

状态模块、Hook 和工作流测试需要覆盖请求标识、过期响应、重复请求、部分完成、错误、重试以及不同操作位置之间的状态隔离。前端测试中模拟 Tauri 调用，只检查调用参数和前端状态变化。Rust 命令测试负责命令注册，bindings 检查负责类型同步，权限测试负责窗口权限；窗口、焦点、插件和 WebView 协作则在真实桌面应用中检查。

### Skill 库工作流

| 场景 | 前端应验证的结果 |
|---|---|
| 固定操作目标 | 添加和删除使用打开流程时的 Environment 与库 ID，不跟随背景选择变化 |
| 成员选择 | 当前可用成员不可重复添加，退役成员可以重新加入，来源预选与安装向导一致 |
| 确认与过期 | 跨主机下载明确确认；预览过期后在当前流程刷新，刷新失败时废弃旧凭据 |
| 执行与重试 | 单次最终确认、执行期间关闭保护、部分结果合并和只重试失败项 |
| 应用状态 | 分别显示已同步、待处理、未验证、需要恢复、已取消和退役清理结果 |
| 读取失败 | 保留已经提交的业务结果和最近可用快照，不因列表或详情刷新失败重发成员命令 |
| 盘点不完整 | 保留已知库和应用位置，展示问题及完整性，禁用需要完整引用证明的操作 |
| 删除与选中项 | 删除其他库时保留当前详情；删除当前库后选择下一项、上一项或空状态；URL 跟随已提交选择 |

## 桌面应用验收

真实桌面验收覆盖窗口、焦点、插件、WebView 和系统交互，前端模拟测试不能替代这些结果。

Skill 库和添加流程至少在 `1000 x 760`、`800 x 600` 和最小 `720 x 520` 内容尺寸下检查固定顶部、独立滚动列表、底部操作、长路径与横向溢出。Skill 内容中的在线图片和外部链接按真实 WebView 与系统网络条件检查。

## 按改动类型选择验证

| 改动内容 | 应完成的验证 |
|---|---|
| 纯 Rust 或业务规则 | 相关单元测试、格式检查和静态检查；影响公共流程时运行完整 Rust 测试 |
| 文件系统、进程或平台分支 | 在目标操作系统上完成编译、Clippy 和 Rust 测试，并运行相应的文件系统或进程测试 |
| WSL 脚本或协议 | 跨平台协议测试、ShellCheck、Linux 脚本测试，以及 Windows、macOS 和 Linux 上的 Rust 验证；涉及真实发行版时增加 Windows 与 WSL 联合检查 |
| Tauri 命令、bindings 或窗口权限 | 命令测试、权限测试、bindings 检查和相关前端测试；涉及应用启动、插件或窗口时增加桌面应用验收 |
| 操作系统安全存储 | 平台适配层测试和 Windows、macOS、Linux 上的编译检查；在对应桌面平台检查系统凭据库的实际读写 |
| 前端页面、状态或工作流 | 相关组件、状态模块或工作流测试，以及 ESLint 和前端构建；涉及真实 WebView 时增加桌面应用验收 |
| 仓库脚本、CI 或发布策略 | 对应脚本测试、工作流检查和受影响的完整 CI 检查 |

具体命令、当前 CI 任务和发布阶段要求见[贡献指南](../CONTRIBUTING.md)。

## 提交前检查

- 缺陷修复对应的测试在修复前能够复现问题，修复后能够识别错误实现；
- 测试名称与实际运行方式一致，测试结果记录了运行平台、使用的真实依赖和尚未检查的场景；
- 本机路径、POSIX 协议路径、换行符、权限位、链接类型和 Shell 能力均采用与各自语义相符的表示及测试方式；
- 外部资源、时间和并发条件可控，测试失败、超时或中断后不会留下进程、监听端口和临时目录；
- 平台专属实现、导入和测试夹具使用一致的条件编译，并在对应操作系统上完成编译与测试；
- 前端异步测试等待用户可见的结果，对象断言和 mock 范围与测试实际关心的接口一致；
- 交付说明以最新运行结果为准，分别列出编译、自动化测试和桌面应用验收结果，并注明尚未验证的平台或环境。
