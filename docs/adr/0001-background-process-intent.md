# 子进程按用户意图区分启动方式

## 背景

Git、WSL 和其他子进程既包含应用内部操作，也包含用户明确要求打开的外部界面。如果每个调用点分别处理 Windows 窗口参数，平台规则容易分叉；如果建立统一执行器接管所有生命周期，又会混合不同协议的超时、取消和输入输出语义。

## 决定

子进程根据用户意图区分为后台进程和前台启动。后台进程通过共享边界构造，并应用对应平台的隐藏窗口策略；前台启动用于用户明确要求打开资源或外部应用。各调用方继续负责自身协议的超时、取消、重试和错误转换。

## 理由

这个划分集中处理共同的平台问题，同时让各业务协议保留自己的生命周期规则，避免形成职责过重的通用进程框架。

## 重新讨论条件

多个业务进程稳定共享同一套完整生命周期协议，或者目标平台提供更统一且可靠的进程模型时，可以重新评估共享边界的职责范围。
