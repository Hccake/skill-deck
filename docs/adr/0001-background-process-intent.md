# 按用户意图区分后台进程与前台启动

## 背景

Git、WSL 和其他子进程既包含应用内部操作，也包含用户明确要求打开的外部界面。如果每个调用点分别处理 Windows 窗口参数，平台规则容易分叉；如果建立统一执行器接管所有生命周期，又会混合不同协议的超时、取消和输入输出语义。

## 决定

根据用户意图区分后台进程与前台启动。后台进程由共享边界负责进程构造和平台界面策略，不自行显示窗口；前台启动只用于用户明确要求打开资源或外部应用。共享边界不接管各业务协议自己的超时、取消、重试和错误转换。

## 理由与重新讨论条件

这个划分集中解决共同的平台问题，同时避免形成职责过深的通用进程框架。只有当多个业务进程长期共享同一套完整生命周期协议，或者目标平台提供了更统一且可靠的进程模型时，才重新讨论扩大该边界。

当前行为由[系统架构](../architecture.md#子进程启动意图)负责说明。
