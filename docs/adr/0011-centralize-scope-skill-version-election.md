# Scope 内 Skill 版本选举采用统一规划 Module

一个 Scope 同时包含通用 Skill 目录和多个 Agent 专用 Skill 目录。同名 Skill 可能具有直接安装版本，也可能来自多个按顺序应用的库。通用目录、各 Agent 专用目录以及多个 Agent 共用的物理目录需要分别确定当前使用的版本。

Skill Deck 先通过统一的 Agent 目录表解析通用 Skill 目录和 Agent 安装选项目录，再为具体 Skill 追加安全目录名。库候选 Source 独立读取库应用记录、catalog 和真实成员定位信息，并把预览证据与纯候选集合分开。安装、复制、移除、管理 Agent 和管理库应用通过 `application/scope_skill_planning` 规划 Scope 内同名 Skill；低层物理目录选举只作为该 Module 的私有实现。

选举 Module 按 `PhysicalTargetKey` 合并指向同一物理目录的位置。任一位置需要直接版本时，直接版本胜出；否则只选择第一个适用的有序库候选。后续候选不会参与胜出判断，只用于识别当前链接是否来自较低优先级或先前应用的库。当前版本中，同一 Scope 应用的所有库共用一组选定 Agent；Agent ID 只说明目录读取者和错误归属，不参与版本胜出判断。

通用 Skill 目录优先使用 Scope 中的直接安装版本，没有直接版本时按库顺序使用第一个同名版本。Agent 专用 Skill 目录只在直接 Skill 关联该物理目录时优先使用直接版本；否则使用关联到该目录且顺序最靠前的库版本。两类版本都不适用时，规划结果不保留该 Skill。通用目录存在直接版本，不会改变其他 Agent 专用目录的选举结果。

统一规划 Module 负责把直接安装 Skill 的 Agent 关联变化和 Skill 库应用关系转换成物理目录计划。链接、复制和转换内容是直接安装版本的写入方式，不改变其选举优先级。调用方继续负责内容取得、lock 或库应用记录、预览凭据、执行和未完成操作。所有相关写入流程都使用非可选的库候选 Source；没有可用库版本时，Source 返回带证据的空候选快照，调用方仍然经过统一选举。每个计划目录都进入执行期复核；无需写入的目录使用只读 `Keep`，旧预览不能授权已经变化的目录写入或应用状态提交。

当前版本没有为历史 Agent 安装项新增独立的所有权记录。规划 Module 能够明确识别已知库链接；为了兼容旧版 Skill Deck 和其他兼容工具已经创建的安装项，有效目录、有效符号链接或 junction 作为该物理目录中的直接版本保留。失效链接可以在存在目标版本时替换；文件等不能作为 Skill 目录处理的条目保持不变，并返回冲突。这项兼容规则不能证明有效条目的创建者，只保证当前操作不会把它误改为库版本。

这项决策替代了安装、复制、移除、管理 Agent 和库应用各自解释优先级的做法。分散处理会让通用目录中的直接版本错误影响其他 Agent 目录，也会在取消直接关联后遗漏库版本恢复。调用方向选举 Module 提交完整的有序候选，由选举 Module 统一取第一项；这让同一套目录识别和版本选择同时服务写入计划、管理 Agent 状态和库管理预览。

正式支持给正在应用的库增删成员并向多个 Scope 传播变化、需要精确区分 Skill Deck 与其他工具创建的 Agent 安装项，或者引入新的 Agent 内容转换与目录形态时，必须重新讨论版本选举输入、所有权证据和跨 Scope 的执行与恢复协议。当前版本继续禁止修改正在应用的库成员。
