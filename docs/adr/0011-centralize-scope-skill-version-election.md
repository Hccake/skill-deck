# Scope 内 Skill 版本选举采用统一规划模块

同名 Skill 可以同时具有直接安装版本和多个库版本，通用目录与各 Agent 专用目录可能使用不同内容。安装、复制、移除、管理 Agent 和管理库应用都需要解释同一套目录关系。

Skill Deck 通过 `application/scope_skill_planning` 统一生成物理目录计划。Agent 目录表负责解析读取位置，库候选模块独立提供有序成员和状态证据，规划模块负责合并同一物理目录并选择版本。各业务流程继续负责内容获取、用户确认、记录提交、执行和后续处理。

集中规划可以避免通用目录中的直接安装版本错误影响其他 Agent 目录，也能在取消直接关联后恢复适用的库版本。库成员同步复用同一规划入口，使预览、写入和管理界面对目录状态采用相同解释。

现有安装项缺少独立的创建者记录，因此规划模块保护无法确认归属的有效内容。这个选择优先保证兼容工具和用户已有内容的安全；需要精确区分安装项创建者，或者支持新的内容转换与目录形态时，应重新讨论所有权证据和规划输入。

逐目录优先级与既有条目处理由[Skill 生命周期](../skill-lifecycle.md#库应用与版本选举)维护。模块边界见[系统架构](../architecture.md#skill-目录规划)，执行期复核和恢复协议见[执行与恢复](../execution-and-recovery.md#skill-变更的执行流程)。
