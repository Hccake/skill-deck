# 诊断信息采用本地日志与结构化业务错误

## 背景

独立诊断层需要长期处理自由文本脱敏、滚动存储、导出格式、用户入口和支持流程。如果产品尚未建立正式的用户支持与诊断交付流程，这些成本不会转化为明确的用户价值。

## 决定

Skill Deck 使用标准本地日志保存开发诊断信息，业务结果使用稳定的错误代码、参数和受控标识。当前产品不建设诊断存储、导出协议或专用窗口入口；内部技术细节保留在本机，不进入前端契约，也不自动上传。

## 理由

当前信息足以支持界面反馈和本机开发排查。独立诊断层还需要长期维护脱敏、滚动存储、导出格式和兼容策略，在缺少正式支持流程时无法形成对应用户价值。

## 重新讨论条件

建立正式支持渠道，并明确用户授权、数据保留和诊断交付流程后，可以重新评估产品级诊断能力。

当前行为由[系统架构](../architecture.md#后端职责)负责说明。
