# 运行维护随 Environment 重新进入而重试

## 背景

Environment 可用后，应用会清理临时内容并重建恢复索引。这类运行维护可能因发行版、权限或文件系统暂时不可用而失败。为它增加独立重试按钮、退避倒计时和长期错误记录，需要维护一套用户很少直接操作的状态机。

## 决定

运行维护失败时，界面展示本次错误。用户处理 Environment 问题后重新连接，或者重启应用，系统根据新的运行时状态重新执行维护。产品不另外维护重试按钮、退避倒计时或长期错误记录。

## 理由

维护失败通常需要先修复发行版、权限或文件系统等外部条件。重新进入 Environment 已经提供自然且低成本的新尝试入口，也避免为低频操作建立独立状态机。

## 重新讨论条件

重新连接或重启无法可靠触发维护，或者用户频繁需要在保持当前 Environment 的情况下立即重试时，可以重新评估独立入口。

当前行为由[系统架构](../architecture.md#environment-运行维护)负责说明；它与[恢复资源](../execution-and-recovery.md#恢复资源)的边界相互独立。
