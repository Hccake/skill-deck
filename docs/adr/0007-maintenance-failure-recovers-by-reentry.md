# 运行维护失败通过重新进入恢复

## 背景

Environment 可用后，应用会清理临时内容并重建恢复索引。这类运行维护可能因发行版、权限或文件系统暂时不可用而失败。为它增加独立重试按钮、退避倒计时和长期错误记录，需要维护一套用户很少直接操作的状态机。

## 决定

运行维护失败后不建立独立的产品级重试流程。用户处理 Environment 问题后重新连接，或者重启应用，系统根据新的运行时事实重新执行维护；旧失败不能永久阻止新尝试。

## 理由与重新讨论条件

维护失败通常需要先修复外部条件，重新进入已经提供自然且低成本的恢复路径。只有用户无法通过重新连接或重启可靠恢复，或者出现必须在不切换 Environment 的情况下立即重试的高频场景时，才重新讨论独立入口。

当前行为由[系统架构](../architecture.md#environment-运行维护)负责说明；它与[恢复资源](../execution-and-recovery.md#恢复资源)的边界相互独立。
